# P0.1 - ReturnRefund <-> Marketplace Order GetOrderReturnContext gRPC

Date: 2026-08-20

## Findings confirmes

- `return-refund-service` possede deja le port applicatif `IOrderGrpcClient` et le DTO `OrderReturnContext`.
- `OrderGrpcClient` retourne encore `DependencyUnavailable`.
- `order-service` expose deja un serveur interne `OrderingGrpcService` base sur `shared/proto/order/v1/order.proto`.
- Le modele Order actuel ne persiste pas `PaymentId`, alors que le contexte de retour doit le fournir pour le lot P0.2.

## Perimetre

- Modifier uniquement Order et ReturnRefund pour le RPC `GetOrderReturnContext`.
- Ne pas modifier Payment sauf reference contractuelle deja existante.
- Evolution additive du proto Order, sans breaking change.

## Contrats

- Ajouter `GetOrderReturnContext(GetOrderReturnContextRequest) returns (GetOrderReturnContextResponse)` dans `order.proto`.
- Ajouter les messages `OrderReturnContext` et `OrderReturnLineContext`.
- Mapper les champs reels Order: order id, buyer/customer id, seller/store, status, delivered date approximative, currency, captured amount, lines livrees.

## Migration

- Ajouter `PaymentId` nullable sur `ordering.orders`.
- Alimenter `PaymentId` au moment du `PaymentCapturedIntegrationEvent` via `ConfirmOrderPaymentCommand`.

## Tests attendus

- Build des projets Order/ReturnRefund impactes.
- Contract-level compilation du proto shared.
- Test manuel a completer ensuite avec vraie base: CreateReturn commande livree.

## Risques restants

- `AlreadyReturnedAmount` et `AlreadyReturnedQuantity` ne peuvent pas etre calcules depuis Order seul sans projection ReturnRefund/Order. Valeur retournee: 0 pour ce lot.
- `DeliveredAtUtc` n'existe pas dans Order; valeur retournee: `CreatedAtUtc` tant que l'historique de statut durable n'est pas ajoute en P1 State Machines.
