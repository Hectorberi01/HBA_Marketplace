# P0.2 - Payment Refund gRPC

## Objectif

Corriger le remboursement ReturnRefund -> Payment pour qu'il soit synchrone en gRPC, idempotent, persisté côté Payment, et publiable en événement Kafka via l'outbox.

## Défauts corrigés

- `return-refund-service` utilisait un client Payment gRPC factice qui retournait toujours `DependencyUnavailable`.
- `financial.proto` exposait `RefundPayment` avec seulement `payment_id`, donc sans montant, devise, refund id, return id ni clé d'idempotence.
- `payment-service` remboursait un paiement total via `Payment.Refund()` sans table de remboursements ni tentative persistée.
- Une relance après timeout pouvait provoquer un deuxième appel PSP, car aucune trace idempotente n'était enregistrée avant l'appel externe.
- Le montant remboursable restant n'était pas vérifié pour les remboursements partiels.

## Décisions

- Ajouter une entité enfant `PaymentRefund` rattachée à `Payment`.
- Utiliser `idempotency_key` comme contrainte unique par paiement.
- Enregistrer une tentative `Processing` avant l'appel PSP, puis `Succeeded` ou `Failed`.
- Retourner la même réponse pour une clé déjà réussie ou déjà en cours, sans rappeler le PSP.
- Refuser tout dépassement du solde remboursable.
- Conserver l'ancien `RefundPayment(payment_id)` comme remboursement total compatible, avec une clé stable dérivée du paiement.
